# Engineering walkthrough

Follow a single offer through the system. Each step names the component that owns the result, so a reviewer can compare the demonstration with the code.

| Step | Implementation decision | Where to inspect it |
| --- | --- | --- |
| 1. Collect the offer | The React form accepts guided posting fields, text, pasted messages or private attachments. The API records the account, time and consent version before queuing processing. | [Workspace](frontend/src/App.tsx), [request schemas](backend/app/schemas.py), [API](backend/app/main.py) |
| 2. Protect the submission | The API checks upload size, declared type and file signature. It encrypts private files and controls access to originals. Report and graph views mask identifiers. | [File validation](backend/app/file_validation.py), [private storage](backend/app/private_storage.py), [privacy helpers](backend/app/privacy.py) |
| 3. Extract inspectable details | The worker parses text and PDF text layers, and uses OCR for supported images and scanned pages. It saves raw and normalized identifiers, extraction method, source location and review status. | [Worker](backend/app/worker.py), [extraction](backend/app/extract.py), [database models](backend/app/models.py) |
| 4. Predict posting risk | The classifier loads exported vocabulary and numeric weights, derives features from the submitted posting and persists a versioned logistic-regression prediction. An input with too little recognized text can abstain. | [Inference](backend/app/posting_model.py), [model export](backend/evaluation/export_hiring_market.py), [prediction display](frontend/src/PostingPrediction.tsx) |
| 5. Verify a claim | Source adapters record the claim, source, retrieval time, outcome and excerpt. For configured employer boards, the verifier checks the employer and title, then uses distinctive three-word phrase overlap to corroborate publication. Corpus matching can run entirely locally. | [Sources](backend/app/source_adapters.py), [vacancy verifier](backend/app/vacancy_verification.py), [findings](backend/app/findings.py) |
| 6. Connect cases | Exact normalized identifiers produce versioned link reasons. At the default threshold of 40, an exact email match contributes 40 points. A URL and its domain on the same host count once. PostgreSQL holds the source records and Neo4j projects their relationships. | [Campaign rules](backend/app/campaign_rules.py), [graph writes](backend/app/graph_outbox.py), [graph rebuild](backend/app/graph_rebuild.py) |
| 7. Review and report | Investigators inspect extraction spans, review evidence relevance and examine campaign links. Corrections and human dispositions retain rationale and history. Markdown and JSON reports draw on the persisted case. | [Case reader](frontend/src/CaseReading.tsx), [evidence graph](frontend/src/EvidenceGraph.tsx), [reports](backend/app/reporting.py) |
| 8. Operate and evaluate | Compose starts PostgreSQL, Neo4j, the API, worker and web proxy. Local tests use disposable records. The evaluation tooling compares predictions with annotations and supports chronological splits. | [Compose](docker-compose.yml), [local setup](LOCALHOST.md), [CI](.github/workflows/ci.yml), [evaluation](backend/evaluation/README.md) |

## Design choices by discipline

- **Full-stack engineering.** The database keeps the submitted material, processing state, evidence and investigator actions together. A refresh or a visit from another authorized user reads the same saved case.
- **Applied machine learning.** The trained posting classifier estimates risk from the available wording and fields. The separate vacancy verifier compares a specific advertised role with retrieved employer material. Repeated identifiers are linked using deterministic rules. Each output has its own meaning and version.
- **Security and product design.** Consent, private uploads, limited retention, authenticated views, redacted exports and a correction path protect the people named in submissions. The interface distinguishes failed checks, uncertainty, observed facts and reviewed conclusions.
- **Deployment engineering.** An installation has a private Compose identity, keys and persistent volumes. A clean clone can run the same workflows from fictional inputs. Operators can stop the stack, keep the data, back up encrypted archives and rebuild the graph from PostgreSQL.
